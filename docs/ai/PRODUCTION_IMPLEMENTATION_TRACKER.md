### Safe isolated test configuration

Backend `.env.test.local` is a separate Supabase project configuration and must remain separate from `.env`. The safety preflight requires `SMARTERP_ENVIRONMENT=isolated_test`, `TEST_DATABASE_URL`, `TEST_DATABASE_PROJECT_REF`, `TEST_DATABASE_ROLE`, `TEST_DATABASE_ISOLATION_TOKEN` (at least 16 chars), and `TEST_DATABASE_AUTHORIZATION=AUTHORIZED_BY_OWNER_FOR_TESTING`; it verifies a database identity marker and rejects matching production project refs. Do not print these values. Check configuration with `node scripts/paymentTestDatabasePreflight.js --config-only`; check live identity with `node scripts/paymentTestDatabasePreflight.js`; only after that succeeds run the schema verifier with `node scripts/verify-ai-audit-schema.js --test`.

The current isolated configuration passes config-only validation, but live identity verification returns `ENOTFOUND aws-0-ap-northeast-1.pooler.supabase.com`. The app `.env` URL is syntactically valid and points to `db.mstwwtprtzfthfgkxbay.supabase.co:6543`, a Supabase dedicated-pooler endpoint shape; the project DNS did not resolve here. Node DNS lookup also returned `ENOTFOUND` for `google.com` and `api.prozync.in`, so this run cannot establish that the Supabase project itself is misconfigured. Supabase's shared transaction pooler uses a dashboard-issued `aws-…pooler.supabase.com:6543` endpoint; its host must not be guessed. No connection secret was printed.

The local Docker Compose file is the development stack and the Docker engine is not running in this workspace. Local ports 5432 and 6379 are not listening. As a result, a local Postgres/Redis-backed integration environment cannot be started or verified here; keep the existing test preflight and use the authorized isolated project when DNS/network access is restored.

## Runtime configuration and rollout

- `GROQ_API_KEY` is required for Groq-backed text and vision requests.
- `GROQ_MODEL`, if set, applies only to the registered general route; unregistered IDs are rejected.
- `GROQ_VISION_MODEL`, if set, must equal the registered vision model ID `qwen/qwen3.8-27b`. This model is currently listed by Groq as preview, so the invoice image capability is preview-dependent.
- `JWT_SECRET` must be configured for signed copilot approvals. Redis must be reachable because approval tokens are single-use and replay-protected there; Redis failure blocks the write.
- Run controlled migration `048_ai_audit_telemetry_schema.sql` after checking the actual production schema/ledger. It is not an automatic startup migration.
- Frontend confirmation UIs submit `approval_token` returned by the proposal response; `confirm_action: true` alone no longer authorizes a copilot write.
- Before migration 048, run `node scripts/verify-ai-audit-schema.js` against a read-only staging connection. Inspect the reported metadata, confirm the recognized baseline and ledger/checksum, snapshot the database, then execute the controlled migration through the forward migration runner and rerun the preflight. The script is a preflight only; it neither applies nor validates data restoration.
- Deployment/push and live production verification were not performed.
