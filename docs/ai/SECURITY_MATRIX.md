# AI security matrix

Audit date: 2026-11-07. This matrix records source-level behavior. It is not a production penetration-test result. Verify deployment middleware order, database RLS, plan state, Redis, and credentials in the target environment before release.

| Surface | Authentication | Company/resource scope | Role and subscription controls | Files, rate/quota, writes, audit |
|---|---|---|---|---|

Confirm every deployment has its prompt-size/rate middleware enabled. |

## Evidence and gaps

- Signed approval implementation: `services/aiActionApproval.js`, `ai/plugins/base.plugin.js`, `/api/ai/confirm-action`, and `routes/businessCopilot.js`.
- Route/registry evidence: `server.js`, `routes/ai.routes.js`, `routes/businessCopilot.js`, `routes/autoSchedule.js`, `routes/predictiveMaintenance.js`, `routes/documents.js`, `ai/plugins/index.js`, `services/aiPluginScope.js`, and `services/aiToolEntitlements.js`.
- Cross-company runtime probes, role matrix tests against two independent companies, RLS execution under production app role, and approval end-to-end database verification remain pending because target DB/Redis access was unavailable.
- AI document route authorization is distinct from employee document management. Do not expose employee files to the technical-document RAG index without explicit ingestion ACL checks.
- `routes/predictiveMaintenance.js` does not currently use `loadPlan`/`requireFeature`; access is role/company gated only. Add subscription enforcement if product policy requires paid AI entitlement.
- The generic AI agent has no plan-quota limit for token/model usage shown at route level. Establish request/token limits at gateway/provider before claiming abuse-resistant production rate control.
